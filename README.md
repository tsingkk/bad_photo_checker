# Kit 图像完整性检测器 (Image Integrity Checker)

一款专为**海量本地照片库、长年冷存储老照片、跨磁盘迁移备份**设计的批量图像完整性检测桌面工具（Python + Tkinter）。

针对照片因存储时间过长（十余年至二十年以上）、磁盘扇区老化/坏道（Bit rot）、复制传输中断、或早期云相册导出失败产生错误占位图等导致的“无法打开、画面截断、半幅灰块”等问题，提供多进程深度像素级扫描与诊断报告导出。

---

## ✨ 核心特性

### 1. 多维度深度损坏识别算法
- **文件头魔数与容器结构校验**
  - 支持 **JPEG** (`.jpg`/`.jpeg`)、**PNG** (`.png`)、**GIF** (`.gif`)、**BMP** (`.bmp`)、**TIFF** (`.tiff`/`.tif`，含 BigTIFF)、**WebP** (`.webp`)、**ICO** (`.ico`) 共 7 大类格式。
  - 校验 JPEG 结束标记 `EOI (0xFFD9)`，同时智能兼容末尾追加 MP4 视频流的现代手机**动态照片（Motion Photos / Live Photos）**。
  - 校验 PNG `IEND` 块与 Chunk CRC、BMP/WebP `RIFF` 声明文件大小、ICO 图层目录偏移以及 TIFF `Strip/Tile` 数据块偏移量。
- **全量像素解码与多帧遍历**
  - 强制解码完整像素流，不局限于文件头检查。
  - 针对 **GIF、多页 TIFF、动态 WebP、MPO（多视角相机照片）** 进行多帧遍历解码，杜绝“仅首帧完好、后续帧截断”的漏检。
  - 自动解除高像素限制，避免高清老底片扫描件、亿级像素照片或全景拼图触发 `DecompressionBombError` 误报。
- **磁盘坏道与老照片专项检测**
  - **扇区清零检测**：识别因磁盘坏道修复（如 `chkdsk`）或复制中断导致的尾部连续 `0x00` 全零扇区填充。
  - **JPEG 半幅死灰块检测**：识别 JPEG 数据流中途异常终止导致的画面底部未初始化中性灰（`RGB 128, 128, 128`）坏块。
  - **物理读取错误捕获**：精确区分普通解码错误、权限拒绝（`PermissionError`）与底层磁盘物理坏道读取异常（`OSError / I/O Error`）。
- **格式错位与“相片读取失败”占位图拦截**
  - 严格拦截扩展名与实际文件头格式不符的文件（如 `.jpg` 内部实际为 `GIF` 等）。
  - 内置错误占位图特征识别，精准检出早期网盘/云相册导出失败生成的 **`130×86` `:( 相片读取失败` GIF 占位图**。

### 2. 高性能多进程架构与流畅交互
- **多进程并发加速**：基于 `multiprocessing` 进程池与有界队列异步投喂，充分利用多核 CPU 性能，支持按核心数自由调节并发度。
- **海量文件防假死 UI**：采用 `80ms` 批量节流刷新机制，即使单次扫描数万张照片，界面依然保持流畅响应，可随时秒级中止扫描。
- **便捷排查交互**：
  - 支持勾选 **“仅显示异常项”** 实时过滤列表；
  - 支持点击任意表头按状态、路径、文件大小数值、故障原因排序；
  - **双击列表中的任意记录**，自动打开系统资源管理器并高亮选中对应照片文件；
  - 表格列宽自适应窗口缩放，遇到超长路径或报错信息时自动撑开列宽并启用底部横向滚动条。
- **多格式报告导出**：支持导出 **CSV 表格**（UTF-8 BOM 编码，Excel 直接打开不乱码）、**TXT 文本报告** 与 **JSON 结构化数据**，报告内自动按“损坏 → 警告 → 正常”优先级排序。

## 🛠️ 环境要求与安装

本项目使用 [uv](https://docs.astral.sh/uv/) 进行 Python 环境与依赖管理。

- **操作系统**：Windows / macOS / Linux
- **Python 版本**：`>= 3.12`
- **核心依赖**：`pillow >= 10.0.0`

### 1. 同步项目环境与依赖

在项目根目录下执行：

```powershell
uv sync
```

### 2. 启动程序

```powershell
uv run python image_integrity_checker.py
```

## 📖 使用说明

1. **选择目录**：点击 **“浏览...”** 按钮选择需要检查的照片文件夹（支持递归扫描所有子目录）。
2. **配置选项**：
   - 在 **“格式”** 栏勾选需要检测的图像格式（可通过 **“全选 / 清空”** 快速切换）；
   - 如只需关注问题照片，可勾选右侧 **“仅显示异常项”**；
   - 在 **“并发进程”** 下拉框中选择进程数（机械硬盘建议 `2 ~ 4` 进程以减少磁头寻道竞争，固态硬盘 SSD 可选 `8` 或更高）。
3. **开始检测**：点击 **“⚡ 开始扫描”**，底部状态栏将实时统计“总计 / 正常 / 警告 / 损坏 / 耗时”。
4. **定位与处理**：
   - 在结果列表中**双击**某条损坏记录，即可在资源管理器中直接定位到该文件进行核实或清理；
   - 点击 **“导出报告”**，选择 `CSV`、`TXT` 或 `JSON` 保存完整检测清单。

## 📊 检测状态与故障类型说明

| 状态标识 | 含义说明 | 常见故障原因 (`error_type`) |
| :--- | :--- | :--- |
| **● 正常** | 图像格式匹配且通过容器结构与完整像素解码校验 | 无 |
| **▲ 警告** | 图像像素可完整解码，但存在非致命元数据异常 | `元数据警告`（如部分老相机非标 EXIF 字段报警，画面本身完好） |
| **✖ 损坏** | 文件无法打开、画面残缺、截断、格式错乱或实为错误占位图 | `格式不匹配 (错误占位图)`：文件实为“相片读取失败”等导出占位图<br>`格式不匹配`：文件扩展名与实际内部编码格式不一致<br>`文件截断`：缺少 EOI / IEND 结束符或实际大小小于容器头声明大小<br>`画面局部损坏`：JPEG 数据流提前中断导致画面底部出现死灰块<br>`扇区清零损坏`：文件尾部出现大段连续 `0x00` 坏道清零扇区<br>`解码错误`：压缩流损坏、哈夫曼表/CRC 校验失败<br>`空文件 (0字节)` / `文件头清零损坏` / `未知或损坏的文件头`<br>`磁盘读取错误`：底层磁盘 I/O 或 CRC 冗余校验错误（提示物理坏道） |
